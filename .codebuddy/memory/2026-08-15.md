## 第二轮改动（真实功能实现）

### 后端 `src-tauri/src/lib.rs`
- 新增依赖：`reqwest`(rustls-tls+blocking)、`zip`、`flate2`、`tar`。
- 新增命令：
  - `parse_toml_tunnels`：正确解析 frpc.toml，含顶部 serverAddr/serverPort/user/[auth] 和 `[[proxies]]` 数组及 `[proxies.transport]` 子表（useEncryption/useCompression），返回 ParseResult。
  - `tunnels_to_toml`：将服务器配置+隧道列表渲染为标准 frpc.toml（含 transport 子表、customDomains、subdomain、bandwidthLimit）。
  - `download_frp`：真实下载 FRP 核心，依次尝试 GitHub 直连 + 镜像站（ghproxy.com / gh-proxy.com / mirror.ghproxy.com），下载后解压 zip(win)/tar.gz(unix)，定位 frpc 可执行文件到 `{app_data_dir}/frp/`。
  - `run_frp`：用 `std::process::Command` 启动 frpc（win 下 CREATE_NO_WINDOW），stdout/stderr 分线程转发为 `frp-log` 事件，后台监控退出并回写状态。用 `FrpState{ running, child(pid) }` 管理。
  - `stop_frp`：win 用 `taskkill /T /F`，unix 用 `kill`。
- 移除了旧的模拟 `start_frp`。

### 前端

## 第三轮修复：解压找不到 frpc

问题：FRP 压缩包内有同名顶层目录 `frp_0.61.1_windows_amd64/`，原解压代码 `splitn(2,'/').nth(1)` 剥离顶层目录时因路径分隔符可能为 `\` 或结构不匹配，导致 frpc.exe 未落在预期位置，报"未找到 frpc"。

修复：
- 解压不再剥离顶层目录，保留原始结构；统一 `\` → `/` 处理。
- 新增 `find_file_recursive(dir, "frpc.exe"/"frpc")` 递归查找可执行文件（大小写不敏感）。
- `download_to_file` 增加 content-type 校验（拒绝 text/html）+ 最小文件大小校验（<100KB 视为无效），防止镜像站返回 HTML 错误页被当压缩包。

下载产物位置（Windows）：`%APPDATA%\com.jlhan.nettool\frp\` 下，压缩包解压后删除，最终 frpc.exe 路径由递归查找返回。
