### 3. OpenFrp 登录（重点）
- 根因一：新版网页登录返回的是 **56 位原始令牌**，必须原样放进 `Authorization` 头；旧代码一律补 `OPENFRP` 前缀，导致「登入凭证无效」。
  - `normalize_token` 改为：旧版 `OPENFRP...` 保留；裸三段式 JWT（`eyJ...`）补前缀；新版原始令牌原样返回。兼容 `Authorization:` / `Bearer` / 引号 / JSON 包装。
- 根因二：面板已移除旧版 Authorization 复制入口。
  - 按 OPENAPI 文档实现 **Remote Login**：`POST https://access.openfrp.net/argoAccess/requestLogin` → 打开授权页 → 每 5s `pollLogin` → Curve25519 + XSalsa20-Poly1305 解密。
  - 新命令：`provider_web_login_start / poll / cancel`；一次性密钥存进程内 `OnceLock<Mutex<HashMap>>`。
  - 前端 OpenFrp 默认「网页登录」Tab：打开授权页、等待动画、已等待秒数、取消/重新打开；成功后自动保存账号并读取隧道。
  - 旧版「密钥登录」保留作兼容；32 位访问密钥会给出明确提示。
- 依赖：`crypto_box = "0.9"`、`getrandom = "0.2"`。

### 4. ChmlFrp 登录
- 鉴权参数仍为 `access_token`（实测 `token` 返回「缺少登录态」，`access_token` 才被识别）。
- 根因：v2 接口字段全小写，旧代码读 `userID/tunnelID/portType/bandDomain/localIP/...` → 登录成功也读不到用户与隧道。
- 修复：`str_of/i64_of/bool_of` 兼容 v2（`id/username/email/usergroup/tunnel/tunnnelCount/localip/nport/dorp/state/...`）与 v1 驼峰字段；域名文本化数组归一化；`dorp` 端口/域名解析；`tunnel_config` 继续按 `access_token + node + tunnel_names` 调用。

## 第三轮：ME Frp 单位修正 / 设置精简 / frp 日志 / 批量管理

### 1. ME Frp 流量与带宽单位（按官方面板逻辑修正）
- 反查官方前端 `me-frp v5.30`（`UserInfoGrid-xtX1NuAZ.js`）确认口径：
  - `traffic` 单位是 **MB**，`>=1024` 显示 GB（两位小数），`<=0` 显示「暂无」——旧代码按 KB 处理导致少 1024 倍；
  - 带宽 `inBound/outBound` 单位是 **1/128 Mbps**，面板显示 `outBound/128` 上行、`inBound/128` 下行（8320 → 65 Mbps）——旧代码按 Kbps `/1024` 处理，显示成 8.1 Mbps。
- `providers/mod.rs` 新增 `mefrp_traffic_text()`、`mefrp_mbps_text()`；`mefrp.rs` 的用户卡与隧道速率统一改用；删除不再使用的 `kb_text()`。
- 实测真实账号 hn13：`traffic=1969711` → `1923.55 GB`，`8320` → `上行 65 Mbps · 下行 65 Mbps`，隧道速率 65 Mbps。

### 2. 设置页精简
