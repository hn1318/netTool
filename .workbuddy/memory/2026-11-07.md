## NetTool 迭代：HTTP(S) 支持 / 令牌显隐 / ME Frp 接入 / 窗口尺寸

### 1. HTTP(S) 隧道
- `config.rs`：http/https/tcpmux 只写 `customDomains`（数组，逗号拆分）与 `subdomain`，绝不写 `remotePort`；stcp/xtcp 写 `secretKey`。新增测试 `http_tunnel_with_subdomain_round_trip`、`parses_http_proxy_from_external_config`。
- 解析侧兼容 `customDomains` 为数组或字符串，兼容第三方生成的 http 配置。
- `runner.rs` 启动前校验：http/https/tcpmux 必须有 customDomains 或 subdomain，否则报错中断（避免 frpc 报 vhost 相关错误）。
- 前端 `api.ts` 增加 `tunnelAccessUrl` / `tunnelRemoteText`；Tunnels 列表与编辑弹窗、Dashboard 远端列均展示 `http(s)://域名` 并可复制。

### 2. 敏感字段显隐

### 3. 第三方服务：ME Frp 5.0 开放 API（新增 `src-tauri/src/provider.rs`）
关键事实（从官方文档 + 官方 Go SDK 源码核对）：
- Base `https://api.mefrp.com/api`；鉴权 `Authorization: Bearer <token>`；UA 不能以 `MEFrp-Client` 开头（用 `NetTool/0.1.0 (...)`）。
- 登录：`POST /public/login` body `{username,password,captchaToken}` → **`data.token`**（访问密钥/用户 Token）。
- 密码登录必须过人机验证：用户打开 `https://www.mefrp.com/3rdparty/captcha?client=nettool`，得到 Base64(`token||client`)，解码取 `||` 前半段作为 `captchaToken`。
- 其他：`GET /auth/user/info`、`GET /auth/proxy/list`（`data.nodes`+`data.proxies`）、`POST /auth/proxy/config`、`POST /auth/proxy/config/multiple`、`GET /auth/user/frpToken`、`POST /auth/proxy/kick {proxyId}`、`POST /auth/proxy/toggle {proxyId,isDisabled}`。
- `proxies[].domain` 是「文本化数组」如 `["mefrp.com"]`，必须归一化。
- 凭据落盘 `{app_data}/providers.json`；导入时把远端配置解析成 `Profile` 并写回 profiles.json，`Profile` 新增 `provider` / `providerProxyIds` 字段。
- 所有 reqwest 命令仍用 `tauri::async_runtime::spawn_blocking` 包装（否则 tokio worker 上 drop runtime 会 panic）。
