## 第五轮：ME Frp 导入报错 / 通知可读性 / 亮色磨砂

### 1. ME Frp 导入一直「操作失败：无效的请求数据（code 400）」
- 根因：官方 5.0 API（MEFrpLib 3.3.0 源码核对）要求 `POST /auth/proxy/config` 的 `proxyId` 为 **整数**；旧代码把前端字符串 id 直接塞进 JSON，服务端判为 400。用真实账号实测：字符串 → 400，整数 → 200 且返回 TOML。
- 修复：`mefrp::profile` 先 `id.parse::<i64>()`，再发送 `{"proxyId": <int>, "format": "toml"}`。
- 新增 `live_config_builds_profile`（需 `MEFRP_TOKEN`）：实测 tunnel 199877 生成配置成功，`tunnels=1`、`authTokenLen=16`。

### 2. 通知弹窗透明度太高
- Toast 不再复用半透明卡片变量：新增 `--toast-bg`（深色 `rgba(24,29,38,.97)` / 亮色 `rgba(255,255,255,.985)`）、`--toast-border`、`--toast-muted`；玻璃模式下也保持接近不透明背景（仅轻微 blur），正文对比度明显提升。

### 3. 亮色模式没有磨砂效果
- 根因：`html.glass` (0,1,1) 的自定义变量被 `:root[data-theme="light"]` (0,2,0) 覆盖，导致亮色下 `--bg-card` 仍是纯白。
- 修复：
  - `html.glass[data-theme="light"]` 显式重设玻璃变量（提高优先级）；
  - 直接给 `html.glass .card/.modal/.sidebar/...` 设置 `background: var(--glass-bg)`，不再依赖变量继承。
- 实测：亮色 + 背景图下卡片呈半透明模糊，背景可见；移除背景后恢复正常纯色外观。

### 验证
- `cargo test --lib` 36 项全过（含 ME Frp 配置真实冒烟）。
- `vue-tsc --noEmit`、`npm run build` 通过。
- 截图检查：亮色磨砂背景正常、通知文字清晰（设置已保存提示）、ME Frp 配置导入成功。

## 第六轮：模糊强度可调 / 背景等比例 / 亚克力高斯模糊

### 1. 模糊强度不能调节
- 根因：`applyAppearance` 只写了 `--glass-blur: Npx`，但 CSS 使用的是 `blur(var(--glass-blur)) saturate(140%)`——自定义属性在 `blur()` 函数里无法按长度参与计算，导致无论滑块怎么动都使用同一个兜底值。
- 修复：`appearance.ts` 直接写入完整滤镜串 `--glass-filter: blur(Npx) saturate(165%)`（同时保留 `--glass-blur` 兼容旧样式）；CSS 改为 `backdrop-filter: var(--glass-filter)`；滑块范围 0–60px。

### 2. 设置中的背景图片改为等比例显示
- 预览区改为 16:9 舞台 + `object-fit: cover`（不再被 `max-height` 压扁变形）。
- 新增「显示方式」三档：等比例铺满（cover）/ 完整显示（contain）/ 拉伸（fill）；
- `Appearance.bgFit` 持久化，并通过 `html[data-bg-fit]` 驱动 `--app-bg-size` / `--app-bg-repeat`。

### 3. 亚克力质感高斯模糊
- 玻璃层统一为：半透明底色 + `blur(Npx) saturate(165%)` + 1px 高光描边 + 内阴影顶部高光；
- 新增内联 SVG `feTurbulence` 噪点纹理（`--noise-url`），以 `::after` + `mix-blend-mode: overlay` 叠加到卡片/工具栏/日志区，模拟 Windows 亚克力（Acrylic）材质；
- 深/亮色分别定义 `--glass-bg / --glass-border / --glass-shadow`，亮色下仍有清晰磨砂。

### 验证
- `vue-tsc --noEmit`、`npm run build`、`cargo check --lib` 全部通过；
- 实机验证：模糊滑块拖动后模糊半径即时变化（8px/9px 时背景明显清晰化）；
- 测试后已移除临时背景图，并将 closeBehavior 复位为 ask。

## 第七轮：页面切换时模糊「顿一下」

### 根因
1. 切换动画带 `transform: translateY(±12px)`：Chromium 在合成层发生 transform/透明度变化时会**重新采样 backdrop-filter**，表现为模糊卡顿一帧；
2. `.content` / `.app-shell` 没有 containment，切换时整页重排导致所有模糊层重新栅格化；
3. 过渡用 `mode="out-in"` + 0.25s，旧页先消失再出新页，视觉上有空档（像“顿住”）。

### 修复
- `styles.css`：`.view-*` 改为**纯淡入淡出 0.16s**，移除所有 transform；
- `html.glass .card / .toolbar / .sidebar` 提升合成层（`translateZ(0)` + `backface-visibility`），避免切换时重算；
- `App.vue`：`.app-shell` 与 `.content` 加 `contain: layout paint`（content 额外 `style`），页面切换只重绘内容区；
- `App.vue` 模板：`<transition name="view" appear>` 去掉 `mode="out-in"`，新旧视图不再串行等待，切换更直接。

### 验证
- `vue-tsc --noEmit`、`npm run build` 通过；
- 实机连续快速切换 9 个页面：模糊不再出现明显停顿，各页渲染正常，无白屏/错位。
