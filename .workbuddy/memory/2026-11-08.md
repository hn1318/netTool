## 第一轮：第三方服务扩展到 4 家（ME Frp / OpenFrp / ChmlFrp / SakuraFrp）+ 页面重排

### 架构重构
- 删除单文件 `src-tauri/src/provider.rs`，改为 `src-tauri/src/providers/`：
  - `mod.rs`：`ProviderMeta` / `ProviderUser` / `ProviderTunnel` / `AccountView` 统一类型 + 账号存储（`providers.json`）+ 通用命令（provider_list/accounts/login_key/login_password/logout/user/tunnels/config/import/kick/toggle/captcha_info/decode_captcha/parse_config）
  - `mefrp.rs` / `openfrp.rs` / `chmlfrp.rs` / `sakura.rs`：各自实现 `login_key / login_password / user / tunnels / profile`
- 前端 `types.ts` / `api.ts` 全部改为通用 `provider_*`；`Providers.vue` 重写为「服务商卡片选择器 + 左侧账号面板 + 右侧隧道表格」两栏布局（<1180px 单栏）。

### 各服务商关键事实（均已用无效凭据实测过错误响应）
- **ME Frp**：`https://api.mefrp.com/api`，`Bearer`；`POST /public/login{username,password,captchaToken}` → `data.token`；配置 `/auth/proxy/config[/multiple]`。
- **OpenFrp**：`https://api.openfrp.net`，头是 `Authorization: OPENFRP<jwt>`（不是 Bearer）；官方**已取消密码登录**，只能粘贴面板「第三方客户端安全登录」的 Authorization；接口 `POST /frp/api/getUserInfo|getUserProxies|getNodeList`，无配置接口 → 用「隧道 + 节点 hostname/port + 用户 token/username」本地组装。
- **ChmlFrp**：文档写 `http://cf-v2.uapis.cn`，**实际 http 会 502，只能用 https**；`GET /login?username&password`、`/userinfo?token=`、`/tunnel?token=`、`/tunnel_config?token&node&tunnel_names`（返回 **INI**）。
- **SakuraFrp**：`https://api.natfrp.com/v4`，`Bearer 访问密钥`；`GET /user/info|/tunnels|/nodes`；`POST /tunnel/config` form `{query, frpc}` 由服务端下发 ini/toml。

### 配置解析
- `config.rs` 新增 `parse_config_text()`：先 TOML，若隧道为空且是 `[common]` 形式则回退 `parse_legacy_ini()`（INI 段 → 每条隧道），ChmlFrp/Sakura 的 INI 也能导入。
- `parse_toml_tunnels` 命令改为走 `parse_config_text`，隧道页导入同时支持 TOML/INI/JSON。

### 验证
- `cargo test --lib`：19 项全过，其中 4 个是针对真实 API 的鉴权冒烟：
  - ME Frp → `登录凭据无效或已过期（401）`
  - OpenFrp → `登入凭证无效, 请重新登入`
  - ChmlFrp → `缺少登录态（code 400）`
  - SakuraFrp → `访问密钥无效（code 401）`
- `vue-tsc --noEmit` + `npm run build` + `cargo build` 通过；应用启动无 panic。
