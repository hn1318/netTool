# 2026-11-06

## NetTool（Tauri 2 + Vue 3 FRP 内网穿透工具）—— 完成三大需求

### 1. 真实流量统计（不再是 Math.random 模拟）
- 方案：在 frpc 与本地服务之间插入**本地计量网关**（`src-tauri/src/traffic.rs`）。
  - 每条 TCP 类隧道 bind `127.0.0.1:0`，frpc 的 `localPort` 指向网关端口，网关转发到真实 `localIP:localPort`。
  - 双向计数：从 frpc 侧读到 = 下行，写回 frpc 侧 = 上行；同时维护并发/累计连接数。
- `runner.rs` 的 monitor 线程每 1s 采样网关字节数算速率，每 2s 拉 `http://127.0.0.1:{webPort}/api/status` 取真实代理状态，经 `frp-traffic` 事件推前端；`get_traffic` / `reset_traffic` 命令。
- UDP 隧道无法做方向统计，UI 标注「无字节统计」。

### 2. frpc 核心下载 + 真实穿透
- `core.rs`：平台/架构自动识别、GitHub releases API 拉版本（失败回退内置列表）、多镜像回退下载（`core-download` 进度事件）、解压、`frpc -v` 校验、`core.json` 元数据。
- `runner.rs::start_frpc`：按配置生成完整 `frpc.toml`（transport/tls/auth/log/webServer + 按类型写 remotePort 或 customDomains 数组或 secretKey），网关端口替换 localPort，写入 `{app_data}/profiles/{id}/frpc.toml`，拉起进程、转发日志、监视退出、关窗回收。
- 大坑：`reqwest::blocking` 在 `#[tauri::command(async)]` 内会 panic（dropping runtime in async context）。**所有 reqwest 命令必须用 `tauri::async_runtime::spawn_blocking`**。

### 3. 多配置管理
- `model.rs`：`Profile`（camelCase）+ `ProfileStore{activeId, profiles}`；`store.rs` 落盘 `{app_data}/profiles.json`，`normalize_profile` 补 id/时间戳。
- 修正历史 bug：`TunnelConfig.local_ip` 之前 serde 只认 `localIP`，而前端发 `localIp` → 反序列化失败导致启动链路不可用。现用 `#[serde(alias = "localIP")]` + camelCase。
- 前端：新增 `views/Profiles.vue`（增删改复制切换/导入导出 TOML）；`App.vue` 集中管理 profiles 并防抖落盘，首次运行把旧 localStorage 配置迁移成一份配置；Dashboard/Settings/Tunnels 改为围绕当前配置工作。

### 验证方式（可复用）
- `cargo test --lib`：8 个测试（网关字节计数真实 TCP、配置渲染、类型字段、TOML 解析新/旧格式、前端字段大小写、GitHub API、平台识别）。
- 真实 frpc `verify -c`：0.61.1 与 0.72.0 均返回 `syntax is ok`。
- 真实 e2e：本地 frps(7000) + node 服务(18080) + 应用自动连接，curl 远端 16000 → 返回服务内容，netstat 确认 frpc 连的是网关端口（51855→51848）。
- 前端 `npx vue-tsc --noEmit` 与 `npm run build` 通过。
